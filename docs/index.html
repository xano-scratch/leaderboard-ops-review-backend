The governed backend under an AI-built ops tool

A game studio's leaderboard ops console, built fast on a frontend builder. One Xano API layer holds the rules it cannot skip: every action is routed by role, sensitive ones wait for a distinct second approver, and each attempt is written to an append-only audit trail.

What it demonstrates

A frontend builder can put a working ops tool in front of staff in a day. The open question is what that tool is allowed to do. The controls here live in the API layer, not the frontend, so nothing the generated UI sends can get around them.

Role-routed access

An ops operator can request an action. Only a lead or admin can approve one, and only for the action types their role covers.

A distinct second approver

A board reset or an entry wipe waits for an approval from a different operator than the one who asked. That is segregation of duties.

An append-only trail

Requests, denials, approvals, and executions all land in one audit trail, each stamped with the rule version that applied.

Access control is API-layer middleware plus role checks (an auth table, a bearer token, a role precondition per endpoint). There is no row-level security anywhere.

API surface

Method and pathWhat it enforces
POST /api:lorb_auth/loginIssues a bearer token for an operator.
GET /api:lorb_auth/meThe current operator and role.
POST /api:lorb_ops/action_requestValidates the target, stamps sensitivity and min role from the rule set, records pending.
GET /api:lorb_ops/actions_queueThe review queue, joined to requester and target.
GET /api:lorb_ops/action_detail/{id}One action with its approvals.
POST /api:lorb_ops/action_approveRole guard and segregation of duties. A denial is audited, then refused.
POST /api:lorb_ops/action_executeRuns only if approved by a distinct operator. Applies the effect.
GET /api:lorb_boards/leaderboards_listBoards with status and entry count.
GET /api:lorb_boards/entries_listRanked entries, with the cheat flag.
GET /api:lorb_audit/audit_queryThe audit trail, filterable, every row stamped with a rule version.
POST /api:lorb_seed/seed_runIdempotent demo data.

Frontend screens

  • Login and role banner. Sign in; the header shows your role so the gating is visible.
  • Leaderboards. Boards and their ranked entries, with the suspected-cheat marker.
  • Request an action. Pick a target and type; sensitive types say a second approver is needed.
  • Review queue. Approve or reject; a blocked attempt shows a banner and is recorded.
  • Audit trail. Every request, denial, approval, and execution, each stamped with the rule version.
